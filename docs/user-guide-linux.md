# Dust on Linux

## Startup and safe mode

`dust` opens the exact current directory and shows the dashboard. Paths passed on the command line are opened through bounded VFS reads. `dust --clean` ignores user configuration. `dust --safe-mode` keeps ordinary reading/editing/saving available but disables plugin loading, project execution, and session restoration. Dust also enters safe mode after two retained crash records; `crash.clear` clears that retained signal. Inspect state with `health.open`, `application.safe_mode.status`, or `dust --health`.

A bounded asynchronous worker atomically maintains user-only `live-health.json` with counts for roots, buffers, dirty buffers, jobs, PTYs, LSP sessions, DAP, pending effects, and failed plugins. The panic hook may embed it in `last-crash.json`; no buffer contents or workspace paths are recorded.

## Keymap policy

`Space` is the bundled value of `<leader>`, not a hardcoded application key. Configure the bounded literal leader sequences and bundled roster in `config.toml`:

```toml
[input.keymaps]
load_bundled_defaults = true
leader = "space"
local_leader = "\\"
```

`keymaps.toml` accepts `<leader>` and `<localleader>` as whole sequence tokens. Every declaration requires a stable bounded lowercase dot-separated `id`. Redeclaring a lower ID replaces or moves it before leader expansion, so the old sequence disappears; an identity-only declaration containing that ID plus `disable = true` disables it without repeating context/keys. Exact unmap/pass-through declarations have their own IDs and context/keys. `:keymap inspect` reports the symbolic declaration and effective sequence; `:keymap inspect id=<id>` reports the stable contribution directly. Setting `load_bundled_defaults = false` omits every bundled mapping and key group while retaining explicit user declarations. Literal `space` remains available for actions that should not follow the leader. Invalid policy/keymaps reject the complete reload and retain the previous snapshot.

When an effective sequence remains a prefix, Dust shows a delayed which-key-style surface generated from that exact resolver state. `[[key_group]]` entries in `keymaps.toml` identify symbolic prefix labels/icons; they use the same replacement and identity-only disable semantics as maps. `[ui.key_hints]` configures enablement, delay, bottom-left/right anchor, row/column/width ceilings, padding/gaps, icon/title visibility, fallback label, and border. Hints are clipped to the editor region and disappear on dispatch, timeout, invalid continuation, paste, focus/context change, prompt activation, or configuration reload. Disabled, unmapped, and pass-through operations are never advertised.

Plugin manifests require a versioned static `contributions` block for namespaced contexts, typed commands, suggested mappings, and key groups. Dust validates and indexes that block before reading Component bytes, then resolves `Bundled < Plugin < User`. User declarations may replace/move or identity-disable plugin defaults and may bind enabled plugin commands. At initial startup these references remain pending until every expected enabled manifest indexes and the complete roster compiles; an indexed command keeps its typed schema but reports unavailable until that exact runtime generation is active. Failure/disable removes exact plugin ownership and restores a safe resolved roster. Changing `[plugins.entries]` while running is rejected before mutation and currently requires restarting Dust; reloads that keep plugin topology unchanged remain transactional.

## Essential controls

- File explorer: `<leader> f e` (bundled as `Space f e`) works from both the startup dashboard and editor Normal mode; `:explore` works from either surface too. The dashboard also exposes `[f] File explorer` directly, while `[e] Open file` intentionally opens the workspace-file picker. The explorer opens as a dedicated 40-cell left-hand tree dock and reflows the dashboard/editor instead of covering it. The workspace root expands automatically; `Enter`/`s` open files while keeping the dock visible and return focus to the editor. Rows use separately themed tree, icon, filename, selection, Git, and diagnostic segments; `[ui.explorer]` selects Nerd Font, Unicode, or ASCII glyph sets and validated width/min/max. Set `bundled_enabled = false` to disable the bundled explorer contribution without disabling workspace files. Children use directory-first natural numeric ordering. Run `:explore` again to focus it. Use `j/k`, `h/l`, `Enter`, `s`, `r`, `.`, `i`, and `Esc`.
- Surface focus: `Ctrl-h/j/k/l` uses the universal compositor rectangles to move spatially among editor splits, the explorer, and the visible terminal in Normal and Visual modes. `Ctrl-h` from a leftmost editor pane enters the visible explorer; `Ctrl-l` returns to the nearest editor window. Directional focus does not wrap, and Insert-mode control characters are unchanged.
- Buffer line: when multiple text buffers are open, the editor region shows a top content line after the explorer. It displays bounded unique-enough names, active and dirty state, and overflow markers that keep the active buffer visible. Normal-mode `Shift-h`/`Shift-l` and `[b`/`]b` select previous/next buffer. `[ui.buffer_line]` controls visibility, formats, markers, and title width. Logical workspace tabs remain separate. Mouse close/select, icons, diagnostics, pin/reorder, and plugin content entries remain pending.
- Horizontal viewport: each split/tab view owns an independent non-wrapped display-cell offset. `[editor.viewport] horizontal_margin = 4` controls retained left/right cursor context and accepts `0..=100`. Tabs, wide characters, combining sequences, line-number gutters, pane borders, resize, and the explorer dock are included in projection. Line numbers are right-aligned to the digit width required by the largest open buffer, so switching tabs/buffers does not move the sign column or editor text; closing that largest buffer or crossing a new digit boundary may resize it. `[editor].gutter_padding = 1` leaves one blank cell after an enabled Git sign before text begins. Oversized line-number separator/padding policy is clamped so every non-empty pane retains one text/cursor cell. Wrapped mode has no horizontal offset. Vertical scroll context remains zero logical lines; configurable vertical/fold-aware scrolloff is not yet delivered.
- Indent guides: enabled by default. Dust draws the configured one-cell `│` in the first whitespace cell of each `indent_width` step without changing the file, including the first content cell. The default blank cell after the Git sign keeps that first guide visually separate. Inactive guides use the subdued theme border color. Dust chooses the guide at or immediately left of the cursor's exact display column and subtly brightens only that enclosing scope with the muted theme color. On an opening/closing delimiter, it selects the delimiter's scope; earlier leading whitespace on that same line still follows the cursor column. Selected text keeps its selection styling. Set `[editor.indent_guides] active_scope = false` to keep guides but disable cursor-driven brightening, `enabled = false` to hide them, or change `character`; active ambiguous-width policy safely falls back to ASCII `|` when necessary.
- Workspace trust: run `:trust`, type `trust this workspace` exactly in the confirmation prompt, and press Enter. Trust is identity-bound and persisted; adding or replacing roots revokes it.
- Rust LSP: after exact workspace trust is ready, opening a saved `.rs` file asynchronously proves a valid nearest Cargo package/workspace within that trusted Dust workspace before automatically starting its host-policy `rust-analyzer` runtime when `[lsp] auto_start = true` (the bundled default). On non-NixOS Linux, a missing server is obtained only through Dust's normal explicit tool-manager install, using the catalog's pinned direct artifact/runtime; automatic LSP start never installs a tool. On NixOS, a catalog LSP found on `PATH` is the default runtime. `:lsp` is an operational language-server manager, not a static catalog: it preselects the active buffer's server and displays the real selected executable, asynchronously probed version, runtime source, lifecycle (`stopped`/`starting`/`running`/`backoff`/`failed`), project sessions, the host-appropriate Dust installation state and the latest bounded probe/server error. Press `p` to open a concrete build list, not a source toggle. The `INSTALL VIA` column always shows the external `PATH` executable plus exactly one host-appropriate Dust fallback: the same verified upstream build processed by `Dust via Nix` on NixOS, or a verified portable `Dust download` on non-NixOS. The Nix and direct-download mechanisms are never mixed in one host's picker; only the row marked `ACTIVE` is launched. Rust Analyzer has two upstream identifiers: standalone executable version `0.3.x` and a date-shaped GitHub release tag. Dust shows them in separate `VERSION` and `BUILD / RELEASE` columns. A rustup-provided PATH executable is labeled `rustup bundled` in VERSION rather than showing the Rust toolchain as the language-server version. Dust retains the raw reported toolchain build in the row's detail note and shows its reported date in BUILD / RELEASE; it is not presented as comparable to standalone `0.3.x`. The bundled managed choices are `0.3.3025` (`2026-08-24`), `0.3.3016` (`2026-08-17.4`), `0.3.3008` (`2026-08-10.1`), `0.3.2997` (`2026-08-03`), and `0.3.2989` (`2026-07-27`); they appear as `Dust via Nix` on NixOS and `Dust download` elsewhere, and mutable aliases such as `nightly` are excluded. `j/k` moves through builds, Enter makes one row ACTIVE, and `i` installs that focused copy. The selected source plus exact Dust-download version is retained in Dust state. If PATH has no matching server, the default `[lsp] nix_workspace_fallback = true` may select an already installed `Dust via Nix` copy; it never installs automatically. Pressing `i` explicitly realizes the generic compatibility package in the private `tools/nix-lsp-workspace` from Dust's pinned flake and lock, verifies the selected upstream artifact checksum, rewrites a qualified GNU ELF interpreter to Dust's private glibc loader, and probes it before activation. Static artifacts remain unchanged and dynamic musl/unknown interpreters fail closed. The profile is a Nix GC root for loader, common libraries, Node, and JDK—not a separate language-server release. Launch executes the processed artifact directly with the validated nested project cwd and does not evaluate Nix. Dust never reads, evaluates, accepts configuration from, or writes a project `flake.nix`. A source file or arbitrary directory alone never launches a server; a nested Cargo project receives its own RA root/session while Dust's enclosing workspace retains trust authority. A pinned selection overrides PATH; otherwise PATH remains first priority. Without an installed compatible artifact/profile Dust does not launch the server; a missing `nix` executable blocks installation but not an already realized runtime. `scripts/qualify-nix-lsp-fallback.sh` installs all five catalog LSPs in isolated Dust state and exercises initialize, completion, shutdown, and exit without a project flake. In the manager, Enter starts the selected available server, `i` explicitly installs the focused host-appropriate Dust fallback, `u` uninstalls only that Dust-owned copy, `x` stops all selected-server sessions, `R` restarts, and `r` rescans executables and reruns bounded version probes. Dust never installs automatically merely because this menu opens and never modifies or uninstalls a PATH executable. On NixOS, installing through `Dust via Nix` creates a Dust-private locked compatibility profile plus the verified upstream artifact without starting a protocol session; make that exact build ACTIVE with Enter, then press Enter in the main manager to start it. `:lsp.server.start` remains an explicit command-line retry. The status line shows `LSP rust-analyzer` while selected; `:lsp.server.status` and `:lspsessions` provide details. `[lsp] inlay_hints = true` is the default: capable servers are queried after startup and debounced synchronized edits, and their bounded labels render as muted inline virtual text that shifts following source without modifying the buffer. `inlay_hint_level = "standard"` preserves each server's normal settings. `"max"` enables adapter-specific maximum detail for rust-analyzer, TypeScript Language Server, and gopls; unsupported adapters keep standard behavior. During startup, empty responses, provisional `{unknown}` labels, and transient `content modified` failures receive five bounded warm-up retries; the settled revision-owned response replaces any provisional projection. Use `:lsp.inlay_hints` to refresh or `:lsp.inlay_hints.toggle` to toggle the runtime setting. Successful start/ready transitions do not leave bottom-left notifications. Work-done progress is stacked at the bottom-right of the editor region with the animated configured Braille spinner and the public server name; internal identities such as `root:1:rust-analyzer` are never presentation labels. Completed work changes to `✓`, remains visible briefly, and then expires. `[ui.lsp_progress]` controls enablement, row/width bounds, right/bottom margins, spinner frames/interval, completed symbol, and completed-row timeout.
- File/grep workflows: normal-mode `<leader><leader>` opens workspace file find; `<leader> s` opens workspace grep. With the bundled leader these resolve to `Space Space` and `Space s`. They are ordinary stable-ID mappings and can be replaced or disabled independently; the future provider pipeline will also make source/ranker/presenter/preview/actions independently replaceable.
- Command palette: normal-mode `<leader> f c` (bundled as `Space f c`) or `:commands`.

## Sessions and navigation

`session.save` captures roots, tabs, recursive split axes/ratios, panes, cursor/selection/logical-line and display-cell scroll state, focus, and the active tab. Restore waits for every unique root-scoped read and swaps in a separately validated editor state only when all files succeed. Recent files, marks, jumps, and changes retain their horizontal display-cell location as well. `navigation.recents`, `navigation.marks`, `navigation.jumps`, and `navigation.changes` expose those lists; `navigation.mark.set name=…` records a mark. Large-file on/off overrides persist by canonical path.

## Built-in syntax

Dust selects only pinned compiled parsers from the canonical buffer path. Rust, TypeScript, TSX, JavaScript/JSX, Go, JSON/JSONC, TOML, and Markdown are delivered. Parsing owns document/language/generation/revision and bounded source/span/fold/indent results; save-as language changes cancel stale ownership. `syntax.status` shows configured language/support/state labels and exact parser capabilities, and `syntax.fold.toggle` controls built-in folds. `syntax.indent.line` manually replaces only the current line's leading spaces/tabs with configured indentation derived from enclosing accepted syntax ranges; closing-range lines outdent, the edit is revision/writability/view checked and undoable, and stale, unsupported, or ceiling-limited data applies no edit. Dust does not claim automatic newline indentation. TOML and Markdown indentation are explicitly unsupported; Markdown block highlighting is partial. Large-file policy may disable syntax.

## Language servers and snippets

TypeScript/TSX and JavaScript/JSX use their protocol-specific `typescript`, `typescriptreact`, `javascript`, and `javascriptreact` IDs; Go uses `go`. An installed matching server auto-starts only for an active saved file after persisted exact workspace trust is accepted and its catalog-defined project policy accepts a real bounded candidate (Cargo, Go module/workspace, Node config/package, or Python project evidence as appropriate); unsupported extensions, unproven projects, missing tools (unless the NixOS-only private Nix-workspace fallback is enabled), untrusted workspaces, safe mode, and `auto_start = false` stay idle. Sessions attach only documents supported by that server definition, close and clear every owning session's URI/replay/semantic/pull-diagnostic state when save-as changes path, language, root, support, or the final buffer view closes, and select a matching root/server session before requests. Stale preflight documents are rejected on path/language/root changes while same-document revision changes refresh the launch snapshot. LSP UI projections carry active server, buffer, view, revision, URI, and language ownership; edits, view/buffer reuse, session changes, and save-as clear revisionless folds and selection ranges before another result may project. Every LSP start or restart consumes fresh trust/root identity validation and canonical execution preflight using the discovered server executable or the validated Nix executable for the private-workspace fallback. Symlinked PATH entries are resolved and validated to a regular executable; on Unix the configured executable name remains `argv[0]`, so rustup-style `rust-analyzer` proxies still dispatch correctly. Each root/server session independently owns its attached-document replay set, restart counter, exponential-backoff deadline, and circuit-open health. An inactive session restarts without stealing active selection.

Hover and signature help use a cursor-relative multiline documentation popup, not the notification row. `[ui.documentation_popup]` controls enablement, width/height, padding, preferred below/above placement, border, and bounded `scroll_step`; theme roles are `documentation_background`, `documentation_border`, `documentation_title`, and `documentation_text`. `lsp.documentation.scroll_up`, `lsp.documentation.scroll_down`, and `lsp.documentation.close` are registered and user-mappable. Dust intentionally ships no default scroll keys for this popup. Movement/edit/paste/focus/new-request/reload changes dismiss it. Structured Markdown rendering and a real-hover-server PTY fixture remain pending.

Completion snippet edits within the selected placeholder atomically update every same-index mirror and recompute subsequent tabstop ranges. Unrelated buffer revisions invalidate the snippet session safely; `snippet.next`, `snippet.previous`, and `snippet.cancel` remain typed commands.

## Tasks, test results, and diagnostics

Tasks, formatters, linters, tests, LSPs, and DAP sessions use fresh trust plus canonical absolute-executable/cwd preflight. The tool manager installs catalog tools only into Dust's private state store, never through a system package manager or a global npm/pip/go/rustup prefix. Direct upstream artifacts are HTTPS-only, SHA-256 pinned, size/path bounded, and probe-checked before becoming available. Each installed managed tool records its exact activated catalog version inside the atomically selected private directory, allowing the manager to distinguish an installed pin from other available versions. The selected tool row reports live download bytes/percentage when a content length is known, then explicit extracting/runtime/package-resolution/build/verification phases. JavaScript packages are exact-version and isolated. Dust's package installer uses a directly runnable `bun` on ordinary Linux without invoking npm or a global prefix; otherwise ordinary FHS-glibc hosts receive Dust's pinned upstream GNU Bun runtime. On NixOS, the same checked GNU Bun artifact is processed through Dust's private compatibility profile, while the profile's pinned Node executes package entrypoints requiring Node semantics. The checksum/version is qualified by `scripts/qualify-bun-runtime.sh`; no system Node/npm path is used. Adapters without a portable upstream artifact remain discovery-only. Managed installation has a source-owned 15-minute deadline. Formatter output becomes one dirty buffer transaction and is never saved automatically. Linter locations for unopened files are read asynchronously under workspace scope; an owner is replaced only after every location snapshot succeeds. Test rows with source locations open through the same checked path.

## Integrated terminal window

Dust bundles a `shell` terminal profile using `/bin/sh`; `[terminals] default_profile` selects the profile opened when none is named. Additional profiles are declared under `[terminals.profiles.<name>]` with an absolute program, explicit argv/cwd/environment, and bounded launch dimensions. For example, a `zsh` profile must be configured explicitly before `:terminal.open zsh` can use it. `:terminal.open` with no argument opens the configured default. Opening requires workspace trust and canonical executable/cwd preflight. Dust owns the PTY and process group.

The selected terminal defaults to a full-width bottom dock beneath the explorer and editor—not a picker—but it owns an ordinary generic window. **Ctrl+/** and **Ctrl+\\** open the default profile, show/focus the selected hidden terminal, or hide it when already focused. Repeated `:terminal.open` commands create independent terminal tabs shown in the title row; Ctrl-Shift-h/l or `terminal.cycle direction=-1/1` switches tabs without respawning their PTYs. A successful `exit` closes only that terminal tab; a nonzero/signal exit keeps its output and shows an error. Default chrome shows the terminal mode and identity, never parser counters or permanent `RUNNING`/`EXIT 0` telemetry.

Press Escape twice to enter terminal Normal mode. Use `h/j/k/l`, arrows, `0`, `$`, `gg`, and `G` over bounded terminal history; `v` or `V` starts characterwise or linewise Visual selection, and `y`/`yy` yanks into ordinary Dust registers. `i`, `a`, or Enter returns to PTY input. A lone Escape still reaches the child after the bounded mapping timeout. Ctrl-h/j/k/l remains host-owned spatial focus. In editor Normal mode, Explorer, and terminal Normal/Visual modes, Ctrl-Left/Right decreases/increases focused width and Ctrl-Up/Down increases/decreases focused height. All bindings are ordinary stable-ID mappings and are remappable.

`[ui.terminal_panel]` configures height bounds, retained workspace height, resize step, divider, tab titles/separator, and terminal mode labels. `terminal.resize rows=…`, `terminal.focus id=…`, `terminal.focus_active`, `terminal.unfocus`, and `terminal.close` remain registered. `terminal.dock edge=bottom size=12`, `terminal.float x=5 y=3 width=80 height=24`, `terminal.fullscreen`, and `terminal.hide` move the same terminal window without replacing its PTY. These wrap generic `window.*` commands; `window.resize.directional direction=left|right|up|down` targets the visibly focused surface. Clicking the terminal body uses the configurable `terminal_mouse` context.

The dock renders fixed cells, wide-cell continuations, bounded styled history, input/Normal/Visual cursors and selection, and typed 16/256/RGB colors with common text attributes. Alternate-screen restoration, cursor visibility, application cursor, bracketed paste, focus, mouse/SGR mouse, scroll regions, origin mode, line insertion/deletion, scroll operations, and IND/NEL/reverse-index are bounded. Full xterm compatibility and persisted processes remain unsupported.

## Debugging

Use `:dap` to install/select catalog adapters or declare absolute adapters under `[debug.adapters.<id>]` with launch/attach definitions under `[debug.sessions.<name>]`. Catalog DAP startup uses the same asynchronous bounded project-root proof as LSP: a file alone never launches an adapter, a malformed nearer boundary fails closed, the nested project controls adapter cwd, and the enclosing Dust workspace continues to own trust/executable scope. `dap.configuration.start name=…` performs fresh trust validation and canonical preflight for both adapter and launch program. Source-debug adapters may use the selected saved source; native adapters require an explicit compiled target through `:dap.session.start <program>` and will not pretend that a `.rs`/`.c` source is executable. Path maps use longest-prefix local↔adapter conversion. Breakpoint toggle/configure, watches, evaluate, threads, frames, scopes, variables, source references, restart, and controls are typed commands.

A debug session may set `run_in_terminal_profile` to an existing terminal profile. Dust accepts a DAP `runInTerminal` request only when executable, argv, cwd, and environment exactly equal that profile, then repeats trust/preflight and starts it through the PTY owner. Other requests receive an explicit failure.

## Workspace resource operations

LSP/plugin text edits always preview and become dirty buffers. Create first checks canonical parent scope and target absence, then creates only a dirty empty editor buffer. Rename/Delete capture canonical source bytes and Linux device/inode plus destination-parent identity. Preview acceptance only stores intents—disk remains unchanged. `workspace.resource.apply` revalidates editor state, bytes, identities, target absence, and root revision before filesystem mutation. Rename updates buffer paths after success; Delete leaves recoverable dirty scratch content. Multiple operations are sequential, not transactionally atomic. Cross-filesystem rename is rejected and never falls back to copying.

## Components and local packages

The universal-window architecture separates durable content, per-window view state, visible window, and workspace-tab graph. Native projection now supports tile, every dock edge, clipped float, one fullscreen window, bounded overlays, and hidden state. Explorer-left and terminal-bottom are ordinary bundled graph rules, and terminal placement preserves the PTY identity. Editor split/focus/resize/close/tab and tiled-swap commands commit editor and graph candidates together; editor dock/float/fullscreen remain unsupported. Dashboard, generic picker/search, problems, task output, LSP logs, and debug/DAP lists have distinct stable graph identities; list surfaces share the picker presenter but their active rectangle, clipping, hit testing, hide/show, and close lifecycle come from the compositor. `[windows] rule = […]` accepts up to 32 strict semantic defaults for these `builtin.*` content types with `automatic`, docked, floating, fullscreen, or hidden placement. Duplicate/unknown/invalid rules and multiple fullscreen defaults reject the whole reload; precedence is bundled, then user, then the supported restored-session rule, then an explicit runtime command. Session state version 2 persists only semantic explorer/selected-terminal placement defaults keyed by content type; it never stores runtime content/view/window IDs, PTY IDs, process state, output, or environment. Statically declared plugin content may now request active-tab docked/floating/fullscreen/hidden windows through `queue-ui-request`; Dust returns later typed results through `take-ui-events`. One opaque exact-generation lifecycle handle owns a host-private content/view/window triple. Retained container/text/list-node/button trees are revisioned, bounded, semantic-style driven, compositor-clipped, and removed with their load generation. The host owns focused node and list scroll; plugin/user mappings in the declared context may remap `surface.retained.focus.next/previous`, `surface.retained.scroll.up/down`, `surface.retained.activate`, and `surface.retained.mouse.select`. User `[windows]` rules may target an enabled plugin content ID only after its static manifest index proves that declaration. The bounded `private_cells` presenter is now available for arbitrary local terminal-cell UI: a statically accepted capability/policy gates it, Dust reports only local dimensions revisions, and plugins submit revisioned full snapshots or dirty patches with style IDs, Unicode lead/continuation cells, optional cursor, and declared-command hit regions. `surface.private.activate` and `surface.private.mouse.activate` are remappable through the declared dynamic context. Geometry changes invalidate old cells; protected prompts remain above and suppress hits. Four host snapshot events (`workspace-metadata-changed`, `active-surface-changed`, `buffer-summary-changed`, and `plugin-surface-changed`) may also be declared statically. Dust coalesces them by kind, reports dropped/coalesced counts, delivers them only during a later plugin command, and retires only bounded acknowledged IDs for that exact load generation; there is no synchronous callback. `picker.plugin.open provider=plugin.<owner>.<provider> query=…` opens the delivered neutral picker-source presenter without replacing bundled file/grep/command pickers. Dust captures context revisions and declaration ceilings, schedules the provider's exact command, accepts only strictly sequenced bounded item chunks, ranks matches host-side, and cancels late output on close/re-query/unload. Provider items cannot choose commands; selecting one may invoke only the static declaration command, and opaque action bytes are not forwarded as arguments in v1. Plugin-private storage is available through bounded later-result get, compare-and-set, expected-revision delete, and sorted prefix-list calls. Keys use a narrow lowercase-ASCII logical alphabet and never become paths; an exact-generation background worker owns checksummed atomic state under Dust's user state directory. Data survives upgrade, disable, uninstall, and rollback until manually removed. It is not encrypted and must not hold secrets. Read-only plugin virtual documents open with `buffer.virtual.open source=plugin.<owner>.<source> key=<opaque>` and refresh with `buffer.virtual.refresh`. Accepted snapshots use ordinary tiled editor text rendering while host-private ownership preserves identities and rejects editing/save/recovery/persistence. `health.virtual.open` and `health.virtual.refresh` dogfood the same path with a bounded read-only Markdown health report while preserving the existing health surface. Non-tiled/writable virtual text remains unsupported. Displayed/writable virtual documents, approved external-TUI attachments, non-picker providers, composable first-party provider workflows, richer retained widgets, and first-party plugin replacement remain later work.

Components implement `wit/dust-plugin.wit`; see `docs/plugin-sdk.md`. There is no WASI or ambient process/filesystem/network authority. Locally supplied package/plugin manifests and component bytes can be installed with `package.install` or updated with `package.update` after workspace trust. Dust performs scoped bounded reads, checksum/store verification, production-host candidate validation, current-runtime activation, acknowledged lock commit, startup activation reconciliation, and bounded garbage collection. A prepared object never changes the active lock. The package worker publishes the lock only after the plugin owner reports `Loaded`; a failure aborts the token and leaves the old generation active. Committed plugin manifests are stored beside immutable objects, checksummed and Component-validated at startup, and a failed startup activation attempts the retained previous lock once. Rollback validates the complete prior activation set before atomically swapping current/previous locks; remove/rollback unload managed runtimes and reconcile the resulting set. `package.list`, `package.verify`, `package.remove`, `package.rollback`, and `package.gc` are available. `package.registry.search`, `package.registry.show`, and `package.registry.install` use only `https://dust.blurskye.dev/registry/v1`. HTTPS uses rustls, zero redirects, independent deadlines, strict content types, streamed byte ceilings, exact immutable identity and SHA-256, atomic quarantine/cache writes, and an integrity-checked bounded offline cache. Direct Git fetching remains explicitly unsupported; Dust never shells out to Git.

## Qualification scripts

`scripts/qualify-linux.sh` contains real staged commands for implementation checks, tests, strict Clippy, release, PTY, advisory, fuzz, soak, and limited-terminal checks. ## Content line

The editor content line shows configured file/scratch/virtual/custom icons, dirty state, diagnostic counts, pins, and close markers. Integrated terminals and external TUIs are separate compositor windows and never appear as editor content tabs. Use `buffer.pin.toggle`, `buffer.move_left`, or `buffer.move_right`; movement stays inside the active pin partition. Left click selects, middle click toggles a text-buffer pin, and right click closes with dirty-buffer protection. Pin/order state survives in-session graph reconciliation but is not persisted after Dust exits. `[ui.buffer_line]` owns visibility, markers, fallback icons, and the bounded extension icon map; every configured marker/icon must be exactly one terminal cell.

## Explorer watching and scrolling

Opening a file starts one silent bounded libgit2 status snapshot for the active root; opening the bundled explorer also retries that snapshot when needed. Modified, added, untracked, renamed, deleted, and conflicted paths propagate to loaded ancestor directories; affected names and their right-side `M`/`A`/`?`/`R`/`D`/`!` markers use the configured `explorer_git` style. Successful Dust saves refresh the visible explorer asynchronously. Use `workspace.git.status.refresh` after later external changes; unchanged frames never rescan Git. Non-repositories open without an error notification.

When `[ui.explorer.watch].enabled` is true, a bounded worker polls entry names and kinds for loaded expanded directories. It refreshes through the normal ignore-aware directory loader, preserving stable rows where possible. Collapsed directories are not recursively watched and editing file contents without changing directory metadata does not trigger refresh. Use `explorer.page_up` / `explorer.page_down`; the mouse wheel over the explorer moves the selection while keeping it visible. Wheel input over a terminal remains terminal input.

## Local Git subset

Opening an active file or Explorer requests Git status automatically; otherwise run `workspace.git.status.refresh` before `workspace.git.status.open` or `workspace.git.hunks.open`. Accepted status decorates files and ancestor directories in the explorer. The active file has a persistent muted box-drawing `│` sign column after its line numbers. It spans every editor-body viewport row—including wrapped continuations and the `~` region below the end of the buffer—so adjacent cells form one continuous rule. Each `~` remains right-aligned where the final line-number digit would appear. Git-owned rows replace that neutral marker with green `│` for added lines, yellow `│` for changed lines, and red `_` for deletions by default. Under wide ambiguous-character policy, the host safely falls back to the one-cell ASCII `|`. `[editor.git_signs]` remaps the `unchanged`, `added`, `changed`, and `deleted` one-cell symbols. After each edit, Dust asynchronously compares an exact immutable snapshot of the unsaved buffer with the Git index, so signs update without saving; superseded revisions are cancelled and rejected. Disabling line numbers, losing exact repository/status/buffer ownership, or exceeding the bounded diff limits hides them. `workspace.git.hunk.stage` requires a trusted workspace. `workspace.git.hunk.reset` resets only the selected unstaged hunk after the exact phrase `reset this hunk`; it preserves the index and other unstaged hunks. Core Git work is queued through libgit2, never a shell or Git CLI.

This is a bounded Gitsigns-style subset. Staged-hunk unstage, stage/reset buffer, hunk navigation, blame/history, commits, remotes, conflict workflows, and broad LazyGit repository interaction are not supported.

## Wrapped navigation and documentation

`[editor.viewport].vertical_margin` is measured in visible terminal rows. Wrapped lines, tabs, wide/combining characters, collapsed folds, pane splits, the gutter, status line, and resize all use one grapheme-atomic visual-row layout for cursor follow, full/half-page scrolling, rendering, and mouse placement. Tabs, wide glyphs, and combining clusters are never split. In a one-cell pane, an otherwise unrenderable wide glyph occupies one row as the configured one-cell replacement (or `?` if that replacement is itself wide); an exactly full line keeps its end cursor on the final cell. Wrapped-row scroll state is runtime-only and resets to the first wrapped row when a saved session is restored.

Hover, signature, and completion documentation use bounded typed sections. Use `lsp.documentation.scroll_up`, `lsp.documentation.scroll_down`, and `lsp.documentation.close`. `lsp.completion.documentation.open` opens documentation for the exact currently owned completion item and rejects stale requests. Markdown is sanitized and displayed as plain clipped source text; links, images, HTML, and rich Markdown styling are not rendered.
